# 2026-10-11 对比报告复核

依据用户提供的 `windogsc_vs_macos_report.html`，对照当前提交和本机运行结果。图标重绘是用户要求，不计为待修差异；语言目标是可切换的中文 / English。

| 报告项目 | 核实与本轮处理 |
| --- | --- |
| 固定中文 | 新增设置「通用 → 语言」，复用原仓库英文目录并补齐 Windows 文案。XAML 文案实时绑定；切换时刷新编辑器导航、属性、时间线、场景名称、录制条与导出控件。用户文本不翻译。 |
| 同一项目重复打开编辑器 | 已确认 `EditorWindow.Open` 总是创建窗口。现在同一应用实例内按完整路径复用已有编辑器，恢复最小化并激活；不同项目仍分别打开。未加入跨进程单实例路由。 |
| 导出失败出现 FFmpeg 原始日志 | 已确认错误提示取异常的最后一行。现在显示可读失败提示，提供重试和「查看日志」；保存设置和项目的失败也进入同一处理流程，重试重置进度。 |
| 34.6 秒导出卡在约 31% | 本机按相同长度、1600×1200、30 fps，叠加缩放、屏幕透视及源坐标柔化，导出成功，尺寸和时长正确。报告中的原项目、完整错误日志和 VM 条件未提供，不能认定根因已修复。可用 `DogSC.UiChecks --report-export <参考视频>` 再现本轮样例；所有输出在结束后清理。 |
| 录制条入镜 | 录制条原来使用 `AllowsTransparency=True` 的 layered HWND，排除调用没有检查结果。现改为普通 DWM 窗口，玻璃边缘由 WindowChrome 提供；调用检查返回值并回读 affinity，失败写入日志。实际用 gdigrab 采集录制条所在区域，图像为背后的内容，录制条未入镜。见 [采集图像](artifacts/layout-reference/capture-exclusion-bar.png)。备忘录使用同一修正；远程桌面和报告 VM 未重复验证。 |
| gdigrab 必然忽略排除设置 | 本机实际采集不支持这个绝对判断。微软 API 也仅承诺特定公开采集机制，依赖 DWM；不可只凭调用成功承诺所有系统环境都能排除。 |
| 崩溃恢复缺失 | 当前存在启动扫描和 `RecoverPartialAsync`，能为已有媒体补全项目。不是完整的断电 / 杀进程恢复验证。 |
| 聚光、摄像头圆角、屏幕 3D 未完成验证 | 现有成片检查验证了聚光区域外变暗、源坐标跟随裁切缩放、摄像头构图与运动，以及 3D 改变画面。摄像头真实硬件和 Mac 实际项目仍需单独核对。 |
| 场景按钮多一步 | 已有直接选择场景的弹出面板；没有预设时按钮显示「保存场景」。不能把无预设项目的文案当成缺少选择入口。 |

本轮验证：256 项核心测试、WPF 语言 / 动画 / 组件检查、FFmpeg 录制和成片自检通过；新增 34.6 秒成片样例完成。原报告的「约 90%」没有被当作本项目验收比例。

剩余实质差异：采集仍是 gdigrab / dshow，窗口录制仍受遮挡影响；iOS 镜像未实现；部分 3D 成片几何按 15 Hz 采样；复杂真实 Mac 多轨项目迁移、真实摄像头 / 麦克风 / 系统声音、4K / 60 fps 与长录制尚未全面验证。设置整体间距、字体抗锯齿和动画观感仍需继续与参考视频并排核对。

技术依据：[Microsoft SetWindowDisplayAffinity 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)、[微软示例仓库中的 WPF 透明窗口复现](https://github.com/microsoft/Windows.UI.Composition-Win32-Samples/issues/56)。
